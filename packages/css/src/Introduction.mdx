# WireLayer for HTML and server templates

`@wirecore/wirelayer-css` contains all components as CSS classes (`.wc-*`) – **generated from the same recipes** as the
Vue, React and React Native components. A test compares the computed styles of the HTML examples with the
React components (light, dark, Ocean).

```html
<html lang="en" data-mode="dark" data-theme="ocean">
    <head>
        <!-- ship dist/wirecore.css and dist/fonts/ side by side – the fonts are included, no CDN -->
        <link rel="stylesheet" href="/assets/wirecore/wirecore.css" />
    </head>
    <body>
        <button type="button" class="wc-button wc-button-outline wc-button-sm">Details</button>
    </body>
</html>
```

`wirecore.css` is self-contained (Tailwind preflight, theme, fonts, all classes). The fonts are licensed under the
SIL Open Font License 1.1 – `dist/fonts/OFL.txt` belongs to them and is shipped along. If you build with
Tailwind v4 yourself, import the sources instead:

```css
@import 'tailwindcss';
@import '@wirecore/wirelayer-tokens/theme.css';
@import '@wirecore/wirelayer-tokens/fonts.css';
@import '@wirecore/wirelayer-css/components.css';
```

## Inside a page with CSS of its own

`wirecore.css` styles the whole page (preflight on `html`, `body`, `button` …). For WireLayer inside a page that
brings its own CSS – a WordPress admin page, a host app – `wirelayer-css embed` writes one file with the chosen
components, scoped to one element:

```sh
npx wirelayer-css embed --scope '#my-app' --components button,input,card,data-table --out assets/wirelayer
```

```html
<link rel="stylesheet" href="assets/wirelayer/wirelayer.css" />
<div id="my-app" data-mode="light">
    <button type="button" class="wc-button">Save</button>
</div>
```

- **Scoped:** components only apply inside the scope element; preflight, theme variables and the base styles apply to
  it and everything inside it. The rest of the page stays untouched.
- **Without `@layer`:** the page's own CSS is usually not in a layer and would beat every layered rule. An id as scope
  (`#my-app`) also outranks its element and class rules.
- **`data-mode` and `data-theme`** work on the scope element as they do on `<html>`. Without `data-mode` it follows the
  system setting – `data-mode="light"` keeps it light inside a light host page.
- **Components** by the names of the class reference, comma separated (`all` for every one); parts that live in a
  component of their own (`card-parts`) come along. `--out` gets `wirelayer.css` and `fonts/` (with `OFL.txt`),
  `--no-fonts` leaves the fonts out.
- **No build tools needed:** the parts are precompiled in the package, the command only puts them together. Commit the
  output or generate it in your build, and run it again after an update of the package.

## Classes

| What                     | Class                    | Example                                   |
| ------------------------ | ------------------------ | ----------------------------------------- |
| Component (root element) | `wc-<component>`         | `wc-button`, `wc-alert`                   |
| Part of a component      | `wc-<component>-<part>`  | `wc-button-icon`, `wc-alert-icon-box`     |
| Variant                  | `wc-<component>-<value>` | `wc-button-danger`, `wc-button-sm`        |
| Flag (true/false)        | `wc-<component>-<name>`  | `wc-card-interactive`, `wc-input-invalid` |

- A variant class applies to the element **and all parts inside it**: `wc-button-sm` on the button also makes the icon smaller.
- Defaults (e.g. `primary`, `md`) need no class.
- States that the framework components set through attributes have the same names in HTML:
  `disabled`, `aria-invalid`, `aria-current`, `aria-busy`, `data-invalid`, `data-disabled`, `data-state="checked"` …

## Without JavaScript

| Component                                                          | Without JS                                                             |
| ------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| Button, IconButton, Badge, Card, Alert, Avatar, Spinner, StatusDot | ✓                                                                      |
| Divider, Skeleton                                                  | ✓                                                                      |
| Fieldset, InputGroup, NativeSelect, Panel, ScrollPanel, Kbd        | ✓                                                                      |
| Timeline, OrgChart, MeterGroup, ProgressCircle, OverlayBadge       | ✓ – values and status as text in the markup                            |
| Highlight, Prose (`wc-prose` for stored editor HTML)               | ✓                                                                      |
| TableOfContents                                                    | ✓ as links (only the framework packages highlight the visible section) |
| Field, Input, Textarea                                             | ✓ – errors through `aria-invalid` + `aria-describedby`                 |
| Breadcrumb, Steps, Progress, Table                                 | ✓ – values in the markup (sorting/paging needs JS)                     |
| Dialog                                                             | ✓ with `<dialog class="wc-dialog">` and `command`/`commandfor`         |
| Checkbox                                                           | ✓ with `<input type="checkbox" class="wc-checkbox-input">` (below)     |
| RadioGroup, Switch, ChipGroup, SegmentedControl                    | display only – the state lives in `data-state`, which JS sets          |
| Select, Menu, Tooltip, Tabs, Toast, Pagination                     | needs JS (keyboard, focus, positioning) – use the framework packages   |
| Accordion, Popover, Drawer, all form controls with a popup         | needs JS – use the framework packages                                  |

A checkbox without JavaScript – the native input right before the control; checked, focus, `aria-invalid` and
`disabled` come from it (partially selected needs the framework packages):

```html
<label class="wc-checkbox">
    <input type="checkbox" class="wc-checkbox-input" name="terms" />
    <span class="wc-checkbox-control">
        <svg class="wc-checkbox-icon" aria-hidden="true"><!-- check mark --></svg>
    </span>
    <span class="wc-checkbox-label">I agree</span>
</label>
```

`@wirecore/wirelayer-vue` and `@wirecore/wirelayer-react` are meant for interactive pages: they bring keyboard
interaction, focus management and ARIA states that plain CSS cannot provide.
